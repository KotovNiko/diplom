# Backend сервиса автоматизации закупок

Дипломный проект: REST API для сервиса заказа товаров в розничной сети
на Django и Django REST Framework.

## Возможности

- Покупатель: регистрация с подтверждением email, вход, сброс пароля,
  каталог с поиском и фильтрами, корзина, адреса доставки, оформление заказа,
  история заказов. В одном заказе могут быть товары разных поставщиков.
- Поставщик: загрузка прайса (YAML файлом или по ссылке), включение и отключение
  приёма заказов, просмотр своих заказов, смена статуса заказа.
- Письма: подтверждение регистрации, сброс пароля, подтверждение заказа клиенту,
  накладная администратору.

## Технологии

Python 3.10+, Django, Django REST Framework, django-filter, PyYAML, requests, SQLite.

## Установка и запуск

```bash
git clone <адрес репозитория>
cd <папка проекта>

python -m venv .venv
# Windows (PowerShell): .venv\Scripts\activate
# Linux / macOS:        source .venv/bin/activate

pip install -r requirements.txt
python manage.py migrate
python manage.py createsuperuser
python manage.py import_products data/shop1.yaml
python manage.py runserver
python manage.py test
```

Сервер: http://127.0.0.1:8000/, админка: http://127.0.0.1:8000/admin/

### Настройки (переменные окружения, необязательно)

| Переменная | Назначение | По умолчанию |
|---|---|---|
| DJANGO_SECRET_KEY | секретный ключ | ключ для разработки |
| DJANGO_DEBUG | режим отладки (1 или 0) | 1 |
| DJANGO_ALLOWED_HOSTS | разрешённые хосты через запятую | 127.0.0.1,localhost |

Письма в режиме разработки не отправляются, а выводятся в консоль сервера.
Токены для подтверждения регистрации и сброса пароля там же
видны строкой `[DEV] ...`.

## Авторизация

После входа (`POST /api/v1/user/login`) возвращается токен. Его передают в заголовке
всех защищённых запросов: `Authorization: Token <токен>`.

## API (префикс `/api/v1/`)

### Пользователь
| Метод и адрес | Описание |
|---|---|
| POST user/register | регистрация (email, password, first_name, last_name, type) |
| POST user/register/confirm | подтверждение email (email, token из письма) |
| POST user/login | вход (email, password), возвращает токен |
| POST user/password_reset | запрос сброса пароля (email) |
| POST user/password_reset/confirm | новый пароль (email, token, password) |
| GET, POST user/contact | список и добавление адресов доставки |
| GET, PUT, PATCH, DELETE user/contact/<id> | один адрес |

### Каталог и корзина
| Метод и адрес | Описание |
|---|---|
| GET products | список; параметры: search, shop, category, price_min, price_max, ordering, page |
| GET products/<id> | карточка товара с характеристиками |
| GET, POST, PUT basket | корзина; тело POST и PUT: список `[{"product_info": 1, "quantity": 2}]` |
| DELETE basket/<id позиции> | удалить позицию |

### Заказы
| Метод и адрес | Описание |
|---|---|
| POST order | подтвердить заказ: `{"id": <корзина>, "contact": <адрес>}` |
| GET order | история заказов |
| GET order/<id> | детали заказа |

### Поставщик (тип пользователя «shop»)
| Метод и адрес | Описание |
|---|---|
| POST partner/update | прайс: файл `file` (form-data) или `{"url": "..."}` |
| GET, POST partner/state | приём заказов: `{"accepts_orders": true}` |
| GET partner/orders | заказы с товарами поставщика |
| PATCH partner/orders/<id> | смена статуса: `{"state": "confirmed"}` |

Статусы заказа: new → confirmed → assembled → sent → delivered.

## Структура проекта

- `backend/` — настройки проекта и корневые адреса
- `orders/models.py` — модели данных
- `orders/serializers.py` — проверка и преобразование данных
- `orders/views.py` — обработчики API
- `orders/permissions.py` — права доступа
- `orders/services/` — импорт прайса, оформление заказа, письма
- `orders/management/commands/import_products.py` — команда импорта
- `data/` — файлы прайсов

## Принятые решения и ограничения

- Корзина — это заказ со статусом `basket`; у пользователя она одна.
- Цена и название фиксируются в позиции заказа при оформлении.
- Статус заказа один на весь заказ, даже если в нём товары нескольких поставщиков.
- Токены подтверждения живут 24 часа, токены сброса пароля 1 час.
- Загрузка прайса по ссылке выполняет HTTP-запрос с сервера (только http/https,
  таймаут, ограничение размера); для публичного сервиса нужна дополнительная защита.
- Остатки списываются при оформлении заказа атомарной операцией в базе.

## Использование AI-инструментов

В ходе разработки проекта применялись большие языковые модели (ChatGPT-4, Claude 3, GitHub Copilot). 
Инструменты использовались исключительно как вспомогательные и для следующих задач:

- **Изучение и объяснение:** разбор сложных концепций Django/DRF 
  (например, работы транзакций, `select_related`/`prefetch_related`, 
  механизмов `clean()` и `full_clean()`, работы `as_view()`).
- **Поиск и устранение ошибок:** помощь в отладке бизнес-логики 
  (например, выявление проблемы N+1 запросов при подсчете суммы заказа, 
  настройка атомарного списания остатков при гонках данных).
- **Помощь с кодом:** генерация шаблонного кода (шаблоны сериализаторов, 
  каркасы ViewSet, настройки роутинга), написание регулярных выражений 
  и составление YAML-структур для тестовых данных.

**Важное примечание:** Весь сгенерированный или предложенный AI код был критически 
осмыслен, адаптирован под архитектуру проекта и протестирован. Понимание каждой 
строки кода подтверждено успешным прохождением ручных тестов (через Postman) 
и автотестов. Никакие конфиденциальные данные в запросах к AI не передавались.
